# HYP Viewer v0.1.1 실사용 검증 체크리스트

이 문서는 **릴리스 -> 기존 앱 업데이트 -> 실제 기능 검증 -> 수정 버전** 흐름을 위한 테스트 절차야.
GitHub CI의 모의 HTTP 테스트와 실제 YouTube/Hitomi 사이트 접속 검증은 별개야.

## A. 기존 데이터 보호와 설치

- [ ] 먼저 v0.1.0에서 **JSON 백업**을 만들어 안전한 곳에 복사해.
- [ ] GitHub Releases의 **v0.1.1** 페이지에서 OS에 맞는 설치 파일을 받아.
- [ ] Android: **정식 서명**된 `HYP_Viewer_v0.1.1.apk`를 v0.1.0 위에 그대로 설치해. 기존 앱을 삭제하지 마.
- [ ] Windows: `HYP_Viewer_Setup_v0.1.1.exe`를 실행해 기존 경로에 덮어 설치해.
- [ ] 앱 실행 후 기존 서재, 즐겨찾기, 읽기 기록이 유지되는지 확인해.
- [ ] 앱의 업데이트 화면에서 버전이 **0.1.1**로 인식되는지 확인해.

> Android에서 서명 충돌 또는 업데이트 불가 경고가 나오면 앱을 삭제하지 말고
> 오류 화면을 공유해. 정식 v0.1.0과 v0.1.1은 같은 서명 키를 사용해야 해.

## B. Shorts 링크만으로 작품 번호 찾기 (핵심)

- [ ] 누구나 볼 수 있고 댓글이 켜진 Shorts 링크를 입력해.
- [ ] **개인 API 키는 비워둔 상태**로 작품 찾기/댓글 조회를 실행해.
- [ ] 유튜브 공개 설명란과 공개 댓글 일부가 로드되는지 확인해.
- [ ] 댓글 속 숫자 후보가 자동으로 표시되는지 확인하고 하나를 확정해.
- [ ] 앱이 실패하면 오류 문구를 확인해. 유튜브에서 댓글을 직접 복사해 붙여넣을 수 있어야 해.
- [ ] 링크를 하나 더 바꿔서 이전 영상의 댓글이 섞이지 않는지 확인해.

> 공개 웹 클라이언트 방식은 YouTube 사이트 변경·동의·접근 제한·지역 조건에 따라
> 실패할 수 있어. 성공 여부와 실제 오류를 기록해 줘.

## C. Hitomi 앱 내 온라인 읽기

- [ ] 접근 및 열람 권한이 있는 실제 작품 번호를 저장해.
- [ ] **앱 내 온라인 읽기**를 선택해 메타데이터/이미지가 로드되는지 확인해.
- [ ] 좌우 넘기기, 확대, 마지막 읽은 페이지 저장이 동작하는지 확인해.
- [ ] **웹 리더 · 시작 페이지 선택**에서 아래 주소 규칙이 맞는지 확인해.
    - 1페이지: `https://hitomi.la/reader/{작품번호}.html#1-`
    - 2페이지: `https://hitomi.la/reader/{작품번호}.html#2-3`
    - 3페이지: `https://hitomi.la/reader/{작품번호}.html#3-4`
- [ ] 외부 브라우저에서 페이지를 넘겨도 앱 진행도는 자동 동기화되지 않는다는 점을 확인해.

> 웹 리더 URL과 실제 이미지 주소는 다르며, 기본 Hitomi 읽기는 자동 CBZ 다운로드와 별개야.
> 사이트에서 접근을 제한한다면 우회하지 않고 실패 원인을 확인해야 해.

## D. 기존 기능 회귀 테스트

- [ ] 오프라인 CBZ/ZIP 읽기
- [ ] 즐겨찾기 및 읽기 기록
- [ ] JSON 백업/복원 (기기 간 이동은 JSON만 사용)
- [ ] Excel 내보내기 (복원 기능은 제공하지 않음)
- [ ] 추가로 설정한 **허가된 JSON 이미지 소스**의 다운로드 승인·취소

## 문제를 전달할 때

플랫폼(Windows/Android), 앱 버전(0.1.1), 작업 버튼, 기대 결과,
실제 결과, 오류 문구/화면, 재현 순서를 알려줘. 개인 API 키·비밀번호는 보내지 마.

문제가 확인되면 **v0.1.2 등 다음 0.x 릴리스에서 수정하고,
새 정식 설치 파일로 다시 업데이트해서 검증**하는 흐름을 유지해.
